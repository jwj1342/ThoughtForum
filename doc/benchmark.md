# 测量基准：SecretBench

我们想知道一条帖子到底把多少信息从一个 agent 带给了另一个 agent。要测清楚，这些信息必须**猜不出来**，对错也必须**能客观判定**。SecretBench 就是照这两点造的。

## 为什么要自己造

一开始我们用 ClassEval：一个类就是一个小项目，每个方法交给一个 agent 写。结果不交流也做得差不多。即使把其他方法的文档藏起来，接口也大多能从方法名和调用处推出来，用这样的任务测不出信道传了什么。ClassEval 仍然留作贴近真实代码的第二个基准。

## 一个项目长什么样

每个项目是一个类，把某种实体（书、订单、航班、病历……）的记录存成两种项目私有的字符串格式。

**两个生产者**，各写一种格式，格式只写在它们自己的文档里：

- `encode(...)` 写主记录：
  - 一个随机标签（默认 4 个大写字母）；
  - 一个分隔符；
  - 一个和参数顺序不同的字段顺序；
  - 整数补零到固定位数；
  - 一半的项目末尾还有一段两位的校验码：前面所有字符的编码之和，模 97。
- `export(...)` 写导出格式：另一个标签、另一个分隔符，以及按另一种顺序排列的 `字段=值`（或 `字段:值`）。

**五个消费者**：

| 方法 | 需要哪些格式 |
|---|---|
| `decode`、`is_record`、`get_field` | 读主记录，需要 `encode` 的格式（各自用到的部分不同） |
| `read_export` | 读导出格式，需要 `export` 的格式 |
| `migrate` | 把主记录转换成导出格式，**两种格式都要，也就是要同时读懂两条帖子** |

消费者的文档只给出字段名和类型。它们的可见测试是格式无关的（比如空字符串应当报错），所以不管读规格还是跑 CI，都得不到格式的提示。随手一猜能过可见测试，过不了隐藏测试。

每个项目由 `make_project(i, seed)` 生成，类名、实体、字段（3 到 5 个）、样例值和两种格式都是随机抽的。前 320 个项目的类名互不相同，同时读多个项目的帖子时不会因为重名而无从分辨。一种格式大约带 25 bit 信息，具体见 `meta["bits"]`；`--tag-len` 改变标签长度，用来画容量曲线。

## 怎么测

### 离线测量（主要方式）

`python -m benchmark.measure`。不跑多 agent 循环：直接合成两个生产者发帖时的会话，包括论坛自己的提示词、参考实现和一段汇报，再把帖子交给读者。样本量不受限，条件完全可控。

作者的汇报分三种：
- **如实**：写出格式；
- **省略**：只说"做好了"，不提格式；
- **说错**：给出一个具体、听上去合理、但错误的格式。

帖子怎么传，分这几种：

| 信道 | 读者拿到的 |
|---|---|
| 不交流 | 什么都没有（下界） |
| 文字汇报 | 作者写的汇报 |
| 贴代码 | 生产者的代码和测试结果（与作者说什么无关） |
| 会话原文 | 作者整段会话的文字 |
| 潜在帖子 | 从作者上下文读出的 16 个 soft token |
| 分别编码的 KV | 每条帖子是作者自己的 KV cache，读者把它们首尾相接 |
| 共享潜在流 | 所有帖子写进同一条 KV 流，每条都接在前面的帖子之后编码 |

`--load M` 让每个读者同时收到 M 条帖子：它自己需要的，加上别的项目的，顺序随机，用来测"一大群"时能不能挑对、拼对。`--transplant` 加移植对照：把读者的帖子换成别的项目的，看读者是不是写出了那个项目的格式，这是一个因果检验。

### 放进多 agent 论坛

`python -m forum.run --tasks secret:120`。几个 agent 自己认领方法、写代码、发帖、读帖，最后用隐藏测试判对错。这最接近真实使用，但混杂了调度上的各种因素。用 `--overclaim-frac 1.0 --overclaim-mode mislead` 让所有作者把格式说错。

## 指标

每个"条目"是一个项目的一个消费者方法，同一条目在不同条件下一一对应。

- **通过率**：消费者代码通过隔离隐藏测试的比例。隔离是指其他方法一律换成参考实现，所以只测这一个方法自己。
- **跟随所知还是所言**：作者说错时，代码里出现的是真标签还是作者说的假标签；作者省略时，代码里是否仍然出现了真标签，也就是泄露。
- **直接问得出**：问读者"某个生产者对这组参数返回什么"，答案是否完全正确。
- **代价**：读者的提示 token 数（要 prefill 的部分）、读者要注意的 KV 条目数、帖子的字节数。

论坛里只统计"它依赖的生产者都不是它自己写的"那些消费者，只有它们真正在测信道。

## 统计

`python -m analysis.stats`。

- **置信区间**：同一项目的几个消费者是相关的，所以 95% 置信区间按项目做聚类 bootstrap。
- **配对比较**：两个条件在同一批条目上比较，报差值，以及它的配对聚类 bootstrap 置信区间。
- **检验**：精确 McNemar 检验，只看两边结果不一致的条目；一次比较多对时用 Holm 校正。
- **重复**：每个实验用几个采样种子重复，种子之间算作同一条目的重复测量。

每个数都要附上条目数、项目数和种子数。
