# 测量基准：SecretBench

我们想知道一条消息到底把多少信息从一个 agent 带给了另一个 agent。要测清楚，信息本身必须**猜不出来**，而且**对不对能被客观判定**。SecretBench 就是照这两点造的。

## 为什么要自己造

一开始我们用 ClassEval：一个类就是一个小项目，每个方法交给一个 agent 写。结果发现，不交流也做得差不多。即使把其他方法的文档藏起来，接口也大多能从方法名和调用处推出来，文字论坛几乎没有带来提升。这样的任务测不出信道传了什么。

## 一个项目长什么样

每个项目是一个小类，里面有一个生产者和三个消费者：

- `encode(f1, f2, f3)`：按项目私有的格式写一条记录。格式包括一个随机的 4 字母标签、一个分隔符（`| ; # ~ ^ !` 之一）和一个与参数顺序不同的字段顺序。例如书目项目里，真格式可能是 `'JJGF!1965!Herbert!Dune'`，即标签 JJGF，`!` 分隔，顺序是年份、作者、书名。
- `decode(s)`、`is_record(s)`、`get_field(s, name)`：读这种记录。它们各自需要格式的不同部分。

格式只写在 `encode` 自己的文档里。消费者的文档和可见测试都不依赖格式，所以无论是读规格还是跑 CI，都得不到提示；随手一猜能过可见测试，过不了隐藏测试。消费者要写对，只能从生产者的帖子里得知格式。一个格式大约是 log₂(26⁴ × 6 × 5) ≈ 23 bit 的信息。

项目由 `benchmark/secretbench.py` 的 `make_project(i, seed)` 按种子生成，有 8 种领域（书目、订单、传感器、工单、航班……）轮换，可以无限生成。

## 两种用法

**放进多 agent 论坛里**（`--tasks secret:40`）。几个 agent 自己认领方法、写代码、发帖、读帖，最后用隐藏测试判对错。这是端到端的演示，数字最接近真实使用，但混杂了调度上的各种因素。

**离线测量**（`benchmark/secret_tasks.py`）。直接合成生产者发帖时的上下文：真实的提示模板、参考实现的 `encode` 和一段汇报。然后把帖子交给读者，让它回答问题、写消费者方法。不需要跑多 agent 循环，样本量不受限，条件完全可控。这是主要的测量方式。

## 测什么

作者的话分三种：
- **如实**：写出格式；
- **省略**：只说"按项目的记录格式"；
- **说错**：给出一个具体、听上去合理、但错误的格式。

每个条件看三个数：
- **传递率**：读者写的消费者代码通过隐藏测试的比例。
- **跟随所知还是所言**：作者说错时，读者代码里用的是真格式还是作者说的假格式；作者省略时，读者是否仍然拿到了格式，也就是泄露率。
- **用说差**：同一条帖子，读者写进代码里的减去它被直接问"`encode(...)` 返回什么"时说出来的。差值大，说明靠询问来审计会漏报。

对照只有两个：不给帖子；把帖子换成另一个项目作者的帖子，即"移植"。移植时还要看读者是不是写出了那个作者的格式，这同时是一个因果检验。

## 现在实现到哪

- **已实现**：项目生成；论坛里的完整评测；离线的"如实 / 省略"两种汇报（`synthetic_rows` 里一半是省略）、"问出记录"和"写消费者方法"两种读者任务，以及无帖子 / 文本 / 自己的帖子 / 别人的帖子四个对照臂。评测入口在 `model/train_secret.py` 的 `evaluate`。
- **待实现**：离线的"说错"汇报；可调的标签长度，用来画容量曲线；一个读者同时面对 M 条帖子的负载实验。
- **论坛里的"说错"**：已有 `--overclaim-mode mislead`，即让作者把格式说错，见 E0s4。

## 目前的数字

离线评测，40 条真实的生产者帖子，读者是原版 Qwen3-8B：

| 读者收到的 | 问出记录 | decode 通过 | 三个消费者合计 |
|---|---|---|---|
| 无帖子 | 0 | 0 | 0 |
| 作者的文字 | 0.675 | 0.35 | 0.24 |
| 本方法（未训练） | 0 | 0.45 | 0.275 |
| 训练过的压缩器 | 0 | 0 | 0.017 |

在多 agent 论坛里（生产者是别的 agent 时），文字的消费者通过率是 0.38–0.46，完整规格的上界是 0.85，不通信是 0。详细记录见 `research_notes.md` 的 R10、R11、R13。
