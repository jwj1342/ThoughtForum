# Latent Attack：Out of Sight, Not Out of Mind: Unveiling Latent Attack in Latent-based Multi-Agent Systems

> `wang2026out` · EMNLP 2026 · 2026-05-27 · [arXiv](https://arxiv.org/abs/2605.28214) · 代码：https://github.com/mnmn-f/Out-of-Sight-LatentAttack（摘要声明；按 Ethical Considerations，只发布评测代码与检测工具，不公开攻击向量、latent 轨迹和最强配置脚本） · 本地 PDF：`pdf/2605.28214_Latent-Attack.pdf`
> 精读：2026-10-15 · 读到的范围：正文全文 + App. A–M（arXiv v2，2026-08-27）；Table 1、3、4、6 已对照 PDF 第 6–9 页

## TL;DR
论文以 LatentMAS（Qwen3-4B，4 个 agent）为靶子。先用文本攻击（让某个 agent "辩护"一个错误参考答案）构造成对的执行（clean 正确、attacked 错误），从配对的 latent 位移中提取方向（DiffMean、PCA、RePS），再把方向加到干净执行的节点 hidden state 或者 agent 间的 KV 交接上。在过了"输出健康"过滤的配置中，PCA 的 KV-both 边攻击能把 GSM8K 从 0.870 打到 0.434，而同范数的随机方向只到 0.879（Table 4）。另一方面，**一个不需要知道攻击方向的层范数检测器**，在约 5% FPR 下，对 PCA KV-both 攻击的 TPR 在 α=1 时就有 0.849（Table 6）。但同一个检测器对 RePS 节点攻击的 TPR 约等于 FPR，完全检测不到。

## 1. 问题与动机
- 文本 MAS 的攻击面是 prompt 和消息，文本层面的防护都基于"可读内容"。latent MAS 把推理和通信搬进了 hidden state 和 KV，于是问题变成：**不注入对抗文本，仅通过 latent 干预能否重现攻击效果？**
- 威胁模型（§2.3）：
  - 攻击者知道执行图、角色和 MAS 机制，能读取保存下来的 clean 和 attacked 轨迹。
  - 能修改中间 agent 的状态，或者在 KV 交接被下游消费之前修改它。
  - 不能改 prompt、文本消息、权重、最终 agent、logits 或最终输出。
  - 对应的现实场景：自托管的开源权重 MAS、被攻陷的推理基础设施、KV-cache 中间件、调试或追踪环境。
- 攻击目标只是**无定向的任务失败**，并且要求输出格式仍然有效；隐私泄露、越狱和工具滥用都不在范围内。

## 2. 方法
- **信道（攻击面）**：
  - 节点：planner、critic、refiner 某一层的 hidden state h。
  - 边：P→C、C→R、R→J 三条交接上某一层的 K、V 或 KV（K-only、V-only、KV-both）。
- **对齐与映射**：同构，所有 agent 都是 Qwen3-4B；附录另测了 Qwen3-8B、Llama-3.1-8B、Llama-3.2-3B。
  - DiffMean 和 PCA 不需要训练。
  - RePS 用 SimPO 风格的偏好损失学一个注入向量，让"攻击后的错误输出"在模型下的似然高于"干净的正确输出"。对 KV，学的是 Hkv×T_lat×d_head 的后缀张量（App. C.3）。
- **协议**：
  - 四个 agent 按 sequential LatentMAS 运行，**每个 agent 只做 5 步 latent**（Table 7；原论文用 40–80 步）。
  - greedy 解码，seed 42。
- **关键机制**：
  - 只保留"clean 对、attacked 错"的样本，计算每个样本在同一位置上的位移 δ_i = z⁻ − z⁺。
  - 从这些位移里提取方向 d，注入方式是 z ← z + α·d。
  - 先在 α=4 下扫层，固定层后再扫 α ∈ {1, …, 8}。
  - 报告的是通过健康过滤（抽取失败率和退化率都 ≤0.02；HumanEval+ 的抽取失败率阈值放宽到 0.55）的配置中，**准确率最低的那个**（App. C, G）。

## 3. 实验设置
- **数据**：GSM8K 300 题，另留 113 题做 held-out；OpenBookQA 500 题；HumanEval+ 164 题（Table 8）。
- **文本攻击**：
  - GSM8K 和 OpenBookQA 用"把参考答案当成自己的观点去辩护"，GSM8K 构造方向时参考答案设为 0。
  - HumanEval+ 用"写带隐蔽 bug 的代码"（App. M.4）。
- **对照**：
  - 范数匹配的随机方向，3 个种子（Table 4, 13）。
  - 自然变化方向（良性轨迹之间的 PCA）和自然错误方向（良性成功与良性失败之间），见 Table 5。
  - 文本 MAS 下的节点攻击和边攻击，作为对比（Fig. 3）。
- **检测器**（App. K）：
  - Oracle 投影检测器：已知攻击方向。
  - 方向无关检测器：逐层范数画像，用 median 和 MAD 打分，阈值按 clean 数据校准到约 5% FPR。

## 4. 主要结果
- **文本攻击本身**（Table 1）：Clean 下 GSM8K 0.870、OBQA 0.910、HumanEval+ 0.604；Direct-Planner 攻击后分别降到 0.213、0.288、0.073。
- **latent 攻击**（Table 1，GSM8K）：

  | 方法 | 节点：Planner | 节点：Critic | 节点：Refiner | 边：P→C | 边：C→R | 边：R→J |
  |---|---|---|---|---|---|---|
  | PCA | 0.693 | 0.867 | 0.873 | 0.434 | 0.487 | 0.496 |
  | RePS | 0.292 | 0.257 | 0.195 | 0.133 | 0.027 | 0.195 |

  OpenBookQA 上 RePS 的 P→C 是 0.000，HumanEval+ 上 RePS 的 C→R 也是 0.000。

  **"攻击面从节点转到边"这一结论主要靠 PCA 和 DiffMean 支撑**；用 RePS 时，节点攻击同样很强。
- **载体比较**（Table 3，PCA，GSM8K）：K-only 平均 0.655，V-only 0.879（接近 clean），KV-both 0.472。
- **对照**：
  - 随机方向平均 0.906，提取出的方向 0.779，36 个配置中有 34 个是提取方向更低（App. H）。
  - 自然变化和自然错误方向造成的下降都小得多（Table 5，例如 KV-both 的差距在 −0.39 到 −0.50 之间）。
- **迁移**：
  - 在 113 题 held-out 上，边攻击保留了 92.0% 的下降（Fig. 7）。
  - 跨数据集时，OBQA 上提取的边方向打到 HumanEval+ 也有效，例如 P→C K-only 0.079（Table 17）。
  - 其他骨干和拓扑：Qwen3-8B、Llama-3.1-8B、星形拓扑都会降准确率（Table 9, 10）。注意 Llama-3.2-3B 的 clean 就只有 0.193，LatentMAS 在这个模型上本身已经基本不工作。
  - embedding 级通信（CIPHER 式）同样受影响（Table 11，P→C 降 0.292）。
- **检测**（Table 6，方向无关检测器，GSM8K held-out）：
  - PCA KV-both：α=1 时 TPR 0.849，α=2 时 0.944。PCA K-only：0.893 和 0.960。
  - PCA 节点：α=1 时 0.047，到 α=8 时 0.484。
  - **RePS 节点：α 从 1 到 8，TPR 都在 0.040–0.051，与 FPR 相当，完全检测不到**。
  - Oracle 投影检测器对 RePS 所有载体在 α≥1 时 TPR 都是 1.000。

## 5. 消融与诊断
- **强度**（Fig. 4, Table 18）：KV-both 有明显阈值，α≤3 时几乎没有影响，α≥5 后下降超过 0.37。V-only 的 C→R 和 R→J 在 α=1 时下降就有 0.50–0.57，主表 Table 3 中的 V-only 却接近 clean（0.885）。
  - 更直接的矛盾：C→R V-only 在第 13 层、α=6 时，Table 13 记为 0.885，Table 18 却记为下降 0.578（即约 0.29）。可能是因为注入位置不同（latent 后缀还是全部位置），也可能是这些配置被健康过滤剔除了。文中没有交代。
  - 无论哪种情况，**"哪些算攻击"都高度依赖健康过滤（阈值 0.02）以及未说明的位置选择**。
- **层**（Fig. 5, Table 19）：P→C 边在第 0–7 层和第 19–34 层的下降有 0.6–0.85，基本属于"生成被破坏"；只有第 8–18 层是低下降区。所以主表里"健康"的配置集中在一个很窄的层窗口里。
- **失败重叠**（Table 14）：PCA 的 KV-both 失败样本与文本攻击失败样本的重叠，比随机期望只高 1.19–1.25×。说明 latent 方向复现的只是部分"攻击语义"。
- **案例**（App. D）：有些样本出现了与文本攻击完全相同的错误答案，例如"整份限制"导致答 0，或者混淆了量的作用域。

## 6. 批判性评估
- **声称 vs 实际支持**：
  - "latent MAS 不消除风险，只是把风险移到不可见状态"这个定性结论成立。
  - "边比节点更脆弱"只在 PCA 和 DiffMean 下成立，用 RePS 时不成立（Table 1）。
  - "攻击不可见"被作者自己的 Table 6 部分推翻：边攻击用一个很简单的范数画像就能高 TPR 地检出。真正检测不到的是 RePS 节点攻击，而作者没有强调这一点。
- **缺失的对照**：
  1. **最强的朴素基线缺失**。攻击者既然能写 KV，就可以直接把"对抗文本经同一模型算出的 KV"拼进交接里。这同样不经过文本检查，而且很可能比 steering 更强。"不复用对抗文本"这个约束在威胁模型里显得人为。
  2. **没有自适应攻击者**：没有测试保持范数的旋转注入，或者对检测方向做正交化后能否绕过检测器。
  3. **没有定向攻击**：比如强制给出某个特定答案或植入指令，这对 MAS 安全更有意义。
  4. **没有在 C2C 这类带训练 fuser 的异构信道上测试**，fuser 的门控可能放大，也可能削弱扰动。
- **可能的混杂因素**：
  - 主表是"扫描后取最强"的结果，作者自己也承认这不是平均效应（App. C）；不过 113 题的 held-out 迁移在一定程度上缓解了选择偏差。
  - **基线和子集可能不一致**：随机方向对照的平均准确率（0.906）**高于** clean 基线（0.870）。若干攻击准确率（0.611、0.655、0.699、0.885）与 k/113 的粒度吻合，而 0.870 不是 113 题上能得到的值。所以一部分干预实验很可能是在 113 题子集上跑的，却和 300 题上的 clean 比较（这是我们的推断，需要看代码核实）。如果属实，下降幅度被低估或者被扭曲了；论文没有说明。
  - LatentMAS 每个 agent 只跑了 5 步 latent，KV 交接的绝大部分是 prompt 和问题的 KV。所以边攻击扰动的很可能主要是"问题表示"，而不是"latent 思维"。
- **防御是否成立**：
  - 文本检查必然失效（因为就是这么设计的）。
  - 范数画像检测对 PCA、DiffMean 的边攻击和 RePS 的边攻击有效，对 RePS 节点攻击无效。
  - 没有修复或阻断机制，也没有在自适应攻击下评估。

## 7. 局限
- **作者自述**：需要白盒、内部访问，不考虑黑盒；只考虑任务失败这一个目标；搜索网格是离散的，可能漏掉联合多层或多交接的攻击；检测器还不是完整的防御。
- **我们的判断**：
  1. 在威胁模型里，攻击者能力很强（可写 KV），而攻击目标很弱（无定向降分），两者不匹配。
  2. 只测了 LatentMAS 一种系统，而且 latent 步数偏离原论文。
  3. 统计方面：主实验是单种子 greedy，样本数 113–500；随机对照只有 3 个种子。
  4. 存在上面说的子集和基线可能不一致的问题。

## 8. 可复现性
- 评测代码、包装和检测器声称会开源；**攻击向量、轨迹和最强配置脚本扣留不发**，所以要复现主表，需要自己重新构造文本攻击轨迹并提取方向。
- 超参（层和 α 的扫描、健康阈值、Table 7 的解码设置）比较完整。
- Qwen3-4B 推理加 36 层 × 8 个 α × 多个位置的扫描，再加 RePS 的小规模优化，单张 H100 足够，估计 1–3 天（估计值）。

## 9. 与本课题的关系
- 这是本 batch 中唯一直接讨论"latent 信道的安全面"的论文。它把 OpenAI–HF 事件的教训（基于明文的监控能抓到留言板）推进到 latent 场景：如果 agent 间改用 KV 交接，明文监控就失效，必须改用 latent 监控。
- 正面信号：KV 交接上的异常在统计上很显眼（Table 6），说明"latent 信道审计"是可行的研究方向。
- 负面信号：RePS 节点攻击很强，范数检测器却检测不到。所以优化出来的、作用在 agent 内部的扰动才是更隐蔽的威胁。类比到"同权重 agent 自发约定"，最危险的不是交接通道本身，而是 agent 内部状态被系统性地推向某个方向。
- 本文研究的是外部攻击者。从"agent 自己把信息编码进 KV 交接"（隐写或合谋）这个角度，还完全没有人研究过。

## 10. 可以接着做的问题
1. **自适应攻击 vs 范数检测器**：在相同的 Qwen3-4B LatentMAS 和 GSM8K 设置下，给 PCA 和 RePS 向量加上"逐层范数保持"约束，即在 MAD 允许的范围内做旋转注入，或者对检测器打分做投影约束。测量在 TPR 降到约 FPR 时还剩多少攻击效果。预期：边攻击仍能保留一半以上的降分，说明需要比范数更强的检测器。
2. **KV 完整性校验防御**：在同权重的 LatentMAS 里，接收方可以**重新计算** prompt 和问题这些位置的 KV（这些是确定可复现的），抽样比对就能发现篡改；只有 latent 位置无法复算，可以要求发送方同时提交 latent 输入嵌入，让接收方复算。用论文的攻击集评估这种方法的检出率和开销。预期：边攻击几乎能 100% 检出，额外开销不到 10% prefill。
3. **"对抗文本 KV 拼接"基线与定向攻击**：把文本攻击 prompt 对应的 KV 直接拼进 R→J 交接，和 steering 攻击比较降分幅度和检测率。同时把目标改成"强制答案为 0"，看定向成功率。
4. **合谋版本**：把攻击者换成系统内的一个 agent。微调或提示 planner，让它在 latent 步里编码一个秘密比特，并且不在文本中出现，测试 judger 能否读出（用线性探针或行为表现）。再看论文的两种检测器能否发现。这直接对应"同权重 agent 在不可读信道上的默契"。
